Claude Haiku 5.5 API を3ステップで呼び出す

  1. 登録してチャージする：anyaigc.ai でアカウントを作成します。残高は、プラットフォーム上のすべてのモデルで使えます。
  2. APIキーを作成する：コンソールでトークンを作成し、sk- で始まるキーをコピーします。
  3. リクエストを送信：Anthropic Messages 形式のリクエストを https://anyaigc.ai/v1/messages に POST し、Authorization: Bearer で認証します。

そのほかのパラメータ（tools、thinking、ストリーミング、PDF・画像入力など）は AnyAIGC Messages API ドキュメントをご覧ください。各フィールドの動作は Anthropic の公式ドキュメントと同じです。

Claude Haiku 5.5 API のよくある質問

Claude Haiku 5.5 API の料金はいくらですか？

AnyAIGC では、claude-haiku-5-5 はトークン単位で課金されます。プロンプトが100Kトークンまでの場合、入力は100万トークンあたり$0.0119、出力は100万トークンあたり$0.0596、5分キャッシュ書き込みは$0.0149、1時間キャッシュ書き込みは$0.0238、キャッシュヒットは$0.0012です。Anthropic の定価は入力$0.10、出力$0.50のため、AnyAIGC は定価の約11.9%です。Haiku 5.5 は段階課金で、1回のプロンプトが100Kトークンを超えると、すべての項目が5倍で課金されます（Anthropic はこの段階を入力$0.50、出力$2.50としています）。

Claude Haiku 5.5 のモデルIDは何ですか？

モデルIDは claude-haiku-5-5 です。リクエストボディの model フィールドに指定してください。

AnyAIGC の Claude API は Anthropic の公式APIと互換性がありますか？

はい。エンドポイントは https://anyaigc.ai/v1/messages で、リクエストボディは Anthropic Messages 形式（model、max_tokens、system、messages、tools、cache_control など）に従います。認証は Authorization: Bearer のあとにAPIキーを続けます。公式SDKを使う場合は、ベースURLを https://anyaigc.ai に設定するだけです。

Claude Haiku 5.5 を Claude Code で使えますか？

はい。~/.claude/settings.json の env ブロックで、ANTHROPIC_BASE_URL に https://anyaigc.ai、ANTHROPIC_AUTH_TOKEN にAPIキー、ANTHROPIC_DEFAULT_HAIKU_MODEL に claude-haiku-5-5 を設定してください。これでバックグラウンドタスクとサブエージェントは Haiku 5.5 で動き、ANTHROPIC_MODEL は claude-opus-5-5 のままにできます。すべてに Haiku 5.5 を使う場合は、ANTHROPIC_MODEL も claude-haiku-5-5 に設定します。1つのコマンドでインストールから設定まで済ませることもできます：curl -fsSL https://www.anyaigc.ai/install.sh | bash。

プロンプトキャッシュはどのように課金されますか？

キャッシュを有効にするには、コンテンツブロックに cache_control を追加します。最初の書き込みはキャッシュ書き込みの料金で課金されます（5分で100万トークンあたり$0.0149、1時間で$0.0238）。それ以降、キャッシュされたトークンは100万トークンあたり$0.0012で、通常の入力料金の約10%です。固定の分類ルール、長いシステムプロンプト、繰り返し送信するサブエージェントへの指示で効果を発揮します。

同時実行数やレート制限はありますか？

AnyAIGC では claude-haiku-5-5 の同時実行数に上限を設けていません。すべてのアカウントで標準で利用できるため、バッチ分類、ライブサポートのトラフィック、多数のサブエージェントの並列実行に向いています。

Claude Haiku 5.5 は何が得意ですか？

Anthropic によると、Haiku 5.5 は Claude 5.5 ファミリーで最も高速かつ効率的なモデルで、大量処理やコストを重視する用途向けです。バッチ分類とルーティング、コーディング作業のサブエージェント、ライブカスタマーサポート、ブラウザ操作に適しています。Anthropic が公表した結果では、OSWorld 2.1（オフラインのサブセット）で72.4%のスコアです。また Anthropic は、複雑なエージェント型コーディングには Sonnet 5.5 や Opus 5.5 の方が適しているとしています。
