01 · JEV-1.13.0 とは

jev-1.13.0：初の公開 System One モデル

チャット LLM が返すのは、解析が必要な文章です。jev-1.13.0 がコードに返すのは、そのまま使える値、つまり確率、選択肢、スコアです。

TypeSafe AI は2026年9月15日に、jev-1.13.0 を初の公開 System One モデルとして発表しました。名前は、人間の判断のうち速く直感的な側面を指すカーネマンの System 1 に由来します。TypeSafe によると、Jev は RLCD（Reinforcement Learning for Calibrated Decisions）と並列サンプラーで学習されており、自由形式のテキストではなく、キャリブレーション済みの確率を伴う型付きの回答を返します。

賢い if 文だと考えてください。判断したい内容を state に入れ、名前と型を持つ質問を questions に定義すると、すべての質問が1回のリクエストで並列に回答されます。質問の数に上限はありません。TypeSafe は、回答が常に要求した型に一致することを保証しているため、解析やリトライのロジックを書く必要はありません。

02 · 質問タイプ

jev-1.13.0 の3つの質問タイプ

questions の各質問に名前を付けます。回答は同じ名前で返ります。

  • type: noul

    noul真である確率

    0から1の確率を返します。instructions で質問するか、criteria に true と false の場合を記述します。

    リクエスト 
    "is_urgent": {
  "type": "noul",
  "instructions": "Does this convey urgency?"
}
    answer 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice選択肢から1つを選ぶ

    criteria で各選択肢を説明に対応づけます。選択肢は1〜255個です。選ばれた選択肢、信頼度、すべての選択肢の確率を返します。

    リクエスト 
    "department": {
  "type": "choice",
  "criteria": {"billing": "…", "sales": "…", "technical": "…"}
}
    answer 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score段階で評価する

    criteria は2〜10段階の順序付き配列です。確率で重み付けしたスコア（小数になることがあります）、信頼度、凡例、各段階の確率を返します。

    リクエスト 
    "frustration": {
  "type": "score",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
    answer 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • 画像や box が必要ですか？

    jev-1.14.0コンテキスト長256k、画像、box

    AnyAIGC の jev-1.13.0 は、コンテキスト長32kのテキスト入力に対応します。画像内の物体の位置を特定する実験的な box タイプ、画像入力、コンテキスト長256kは、同じ料金の jev-1.14.0 で利用できます。

    切り替える 
    "model": "jev-1.14.0"

04 · ユースケース

jev-1.13.0 が向いている用途

コードが分岐、並べ替え、アラートの根拠にできる結果を必要とする場面で使えます。

  • 01 · choice

    分類とインテント

    メッセージ、商品、ドキュメントを固定のカテゴリに振り分け、それぞれに確率を付けます。確信度の低いものは人間または LLM に回せます。

  • 02 · choice + noul

    チケットのルーティング

    1回のリクエストで、どのチームの担当か、緊急かどうか、顧客がどれだけ不満を感じているかがわかります。誰に渡し、キューのどこに置くかを決められます。

  • 03 · score

    リスクスコアリング

    取引、注文、アカウントを、独自に定めた段階でスコアリングします。スコアは確率で重み付けした小数なので、しきい値を設定しやすくなります。

  • 04 · noul

    コンテンツモデレーション

    コメントやユーザー生成コンテンツがポリシーに違反していないかを確認します。ルールごとに独立した質問にして、並列に回答させます。

  • 05 · noul

    LLM ガードレール

    LLM の前後にチェックを追加します。ジェイルブレイクやプロンプトインジェクションを検出したり、回答が提供したソースに沿っているかを確認したりできます。

  • 06 · score

    LLM-as-judge による採点

    LLM-as-judge 評価の一部を置き換え、回答を段階で採点できます。課金は入力のみです。arXiv の論文では、ルーブリック形式の品質判定は苦手とされているため、まず抜き取りで確認してください。

  • 07 · if

    賢い if 文

    テキストから条件を取り出します。返金の依頼か、競合他社に言及しているか、顧客が折り返しの電話を希望しているか、といったことです。回答はそのままロジックに組み込めます。

  • 08 · map-reduce

    大規模バッチ処理

    数百万件のレコードを1件ずつラベル付けし、結果を集計します。同時実行数の上限がなく出力が無料なので、オフラインのバッチ処理に向いています。

  • 09 · リアルタイム

    リアルタイムアプリ

    TypeSafe は、一般的な応答時間を約100 msと報告しており、ユーザー向けのリクエスト経路の中に組み込めるほどの速さです。

06 · 制限事項

公開前に制限を確認してください

TypeSafe の公式ガイダンスに基づく内容です。コードで計算できることはコードに任せ、1つの質問では1つのことだけを尋ねてください。

  • 文言を文字どおりに読む意図した質問ではなく、書かれた質問に答えます。表現は正確にしてください。
  • 計算機ではありません計算や数え上げは避け、コードで処理してください。
  • 日付とマルチホップが苦手日付の比較や複数段階の推論は、分解してから Jev に渡してください。
  • 無関係な状態は逆効果無関係なテキストが大量に含まれる state は、精度を下げます。必要なものだけ送ってください。
  • プロンプトインジェクションのリスクstate に信頼できないコンテンツが含まれると、回答が左右されることがあります。重要なフローでは対策を入れてください。
  • 最初の選択肢への偏り選択式の質問では、最初の選択肢がわずかに選ばれやすくなります。順番をシャッフルして確認してください。
  • テキスト生成は不可チャット、要約、書き換えはできません。文章が必要な場合は LLM と組み合わせてください。
  • 英語が最も得意他の言語でも動作しますが、精度は下がります。多言語の改善が最も大きいのは jev-1.14.0 です。

08 · クイックスタート

3ステップで jev-1.13.0 API を呼び出す

Jev は OpenAI 互換ではありません。通常の HTTP で /v1/systemone を呼び出してください。

  1. 登録とチャージ：anyaigc.ai でアカウントを作成します。残高はすべてのモデルで共通です。
  2. APIキーを作成：コンソールで sk- で始まるキーを作成し、環境変数 ANYAIGC_API_KEY に保存します。
  3. リクエストを送信：https://anyaigc.ai/v1/systemone に POST し、model に jev-1.13.0、あわせて state と questions を指定します。レスポンスは同期で返るため、ポーリングは不要です。

リクエストは32kトークン以内に収めてください。AnyAIGC では jev-1.13.0 のコンテキスト長は32kトークンです。これより長い入力は、複数のリクエストに分割するか、state から無関係なテキストを削るか、コンテキスト長256kの jev-1.14.0 に切り替えてください。

レスポンスの値は AnyAIGC API ドキュメントに基づいています。model には実行されたバージョンが返り、usage.output_tokens は課金されません。不正なボディは 400、不正なキーは 401 を返し、エラーボディの形式は {"error": {"code", "message", "param", "type"}} です。すべてのパラメータは AnyAIGC System One API ドキュメントを参照してください。

FAQ

jev-1.13.0 API のよくある質問

jev-1.13.0 とは何ですか？

jev-1.13.0 は、TypeSafe AI の System One モデルである Jev の最初の公開バージョンで、2026年9月15日に発表されました。System One は、カーネマンのいう速く直感的な判断にちなんで名付けられています。判断したい内容（state）と型付きの質問を送ると、Jev は自由なテキストではなく、キャリブレーション済みの確率を伴う型付きの回答を返します。AnyAIGC ではコンテキスト長32kトークンで、noul、choice、score の質問タイプに対応しています。

jev-1.13.0 は非推奨ですか？

いいえ。2026年10月14日に新しいバージョン jev-1.14.0 がリリースされましたが、jev-1.13.0 は AnyAIGC で引き続き呼び出せ、提供終了日も発表されていません。TypeSafe は、jev-1.13.0 を終了する場合は60日前に通知するとしています。既存の連携はそのまま使い続けられますが、新規プロジェクトには jev-1.14.0 をおすすめします。

jev-1.13.0 API の料金はいくらですか？

AnyAIGC では、jev-1.13.0 は入力100万トークンあたり$0.0227で、出力は無料です。課金はトークン単位で、対象は入力トークンのみです。たとえば、入力300トークンのリクエストを1,000,000件送ると300Mトークンで、$6.81になります。同時実行数は、すべてのユーザーで上限なしです。最新の料金は AnyAIGC モデル一覧で確認できます。

jev-1.13.0 と jev-1.14.0 の違いは何ですか？

jev-1.13.0 は最初の公開リリース（2026年9月15日）で、コンテキスト長32kトークン、テキスト入力、noul、choice、score の質問タイプに対応しています。jev-1.14.0（2026年10月14日）は全体的に小さな改善があり、TypeSafe によると最も向上したのは多言語です。AnyAIGC ではコンテキスト長256kトークンで、実験的な画像入力と box 質問タイプが加わります。料金はどちらも同じです。

jev-1.13.0 API は OpenAI 互換ですか？

いいえ。Jev は TypeSafe の System One API を使います。POST https://anyaigc.ai/v1/systemone のボディに model、state、questions を指定し、レスポンスには answers と usage が含まれます。messages や choices はないため、OpenAI SDK では呼び出せません。requests、fetch、cURL などの通常の HTTP と、いつもの Authorization: Bearer <API Key> ヘッダーを使ってください。呼び出しは同期で、ストリーミングもタスクのポーリングもありません。

jev-1.13.0 の制限事項は何ですか？

TypeSafe によると、Jev は文言を文字どおりに読み、計算機ではなく（計算や数え上げは避けてください）、日付の比較やマルチホップの質問が苦手で、state に無関係なテキストが多いと精度が落ち、プロンプトインジェクションの影響を受けることがあり、choice の質問では最初の選択肢をわずかに選びやすい傾向があります。テキストは生成しません。英語が最も得意で、他の言語でも動作しますが精度は下がります。第三者の arXiv 論文でも、低リソース言語、ノイズのあるラベル、ルーブリック形式の品質判定が苦手であることが報告されています。
