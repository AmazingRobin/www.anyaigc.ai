02 · 質問タイプ

jev-1.14.0 の4つの質問タイプ

questions で各質問に名前を付けます。回答は同じ名前で返り、すべて並列に計算され、質問数の上限はありません。

  • type: noul

    noul真である確率

    instructions で質問するか、criteria {"true": "…", "false": "…"} で両方の側を記述します。0から1の確率を返します。

    answer 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice選択肢から1つを選ぶ

    criteria は選択肢名と説明の対応表で、1から255個の選択肢を指定できます。選択結果、信頼度、各選択肢の確率を返します。

    answer 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score段階で評価する

    criteria は2から10段階の順序付き配列です。確率で重み付けしたスコア（小数）、信頼度、凡例、各段階の確率を返します。

    answer 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · 1.14 で追加

    box物体の位置を特定 実験的

    assets に画像を入れ、ヘッダー TypeSafe-Danger-Zone-Images: true が必要です。TypeSafe のドキュメントによると、回答には物体の上端・下端・左端・右端が0から1の割合で含まれ、あわせて信頼度が返ります（null になることがあります）。

    リクエスト 
    "mug": {"type": "box", "instructions": "the coffee mug in `photo`"}

07 · 制限事項

公開前に制限を確認してください

TypeSafe 自身のガイダンスに基づく内容です。コードでできることはコードに任せ、1つの質問では1つのことだけを尋ねてください。

  • 文字どおりに解釈意図した質問ではなく、書かれた質問に答えます。表現は慎重に選んでください。
  • 電卓ではありません計算や数え上げは避け、コードで処理してください。
  • 日付と多段階推論日付の比較や複数ステップの推論は、分解してから Jev に尋ねてください。
  • 無関係な state は逆効果256k の余裕があっても、質問に必要な内容だけを送ってください。
  • プロンプトインジェクションstate に信頼できない内容が含まれると、答えが左右されるおそれがあります。重要な場面では対策を追加してください。
  • 最初の選択肢への偏りchoice 質問では、最初の選択肢がわずかに選ばれやすくなります。順番を入れ替えて確認してください。
  • テキスト生成なしチャット、要約、書き換えはできません。文章が必要な場合は LLM と組み合わせてください。
  • 画像は実験的機能TypeSafe は、画像入力と box を本番環境ではまだ推奨していません。

10 · 画像 & box

jev-1.14.0 での画像、box、長いコンテキスト

画像を Base64 エンコードして assets に入れ、state からそのプレースホルダーを参照し、ヘッダーを1つ追加します。

実験的機能です。TypeSafe のドキュメントによると、画像は PNG または JPEG で、16 MiB 以下、1辺280〜1568 px である必要があり、通常の入力トークンとして課金されます。リクエストには TypeSafe-Danger-Zone-Images: true が必要です。TypeSafe は、画像と box を本番環境ではまだ推奨していません。コンテキスト長256kにも、オプトイン用のヘッダー TypeSafe-Danger-Zone-Long-Context: true が必要です。AnyAIGC はこれらのヘッダーと assets をそのまま転送します。

box は位置を特定するだけです。この例では noul の質問を加え、box を使う前に対象物があるかどうかを確認しています。プレースホルダーは単なる文字列なので、state 内の他のテキストと衝突しないよう、画像ごとに新しいランダムな ID を使ってください。長い入力では、同じヘッダーに TypeSafe-Danger-Zone-Long-Context: true を追加します。

FAQ

jev-1.14.0 API のよくある質問

jev-1.14.0 とは何ですか？

jev-1.14.0 は、TypeSafe AI が初めて公開した System One モデル Jev の最新バージョンで、2026年10月14日にリリースされました。System One の名前は、ダニエル・カーネマンの言う速く直感的な判断に由来します。判定したい内容（state）と型付きの質問をまとめて送ると、Jev は自由なテキストではなく、較正された確率を持つ型付きの答えを返します。TypeSafe によると、RLCD（Reinforcement Learning for Calibrated Decisions）と並列サンプラーで学習されています。

jev-1.14.0 は jev-1.13.0 から何が変わりましたか？

TypeSafe によると、jev-1.14.0 は全体的に小幅な改善があり、特に多言語の入力で大きく向上しています。また、画像内の物体の位置を特定する実験的な box 質問タイプが追加されました。AnyAIGC では、jev-1.13.0 のコンテキスト長が32kなのに対し、jev-1.14.0 は256kトークンです。料金はどちらのバージョンも同じです。

jev-1.14.0 API の料金はいくらですか？

AnyAIGC では、jev-1.14.0 は入力100万トークンあたり$0.0227で、出力は無料です。課金されるのは入力トークンのみで、画像も通常の入力トークンとして数えられます。たとえば、入力300トークンのリクエストを1,000,000回送ると300Mトークンになり、料金は$6.81です。同時実行数はすべてのユーザーで上限がありません。最新の料金は AnyAIGC のモデル一覧で確認できます。

コンテキスト長256kはどう使いますか？

AnyAIGC のモデル一覧では、jev-1.14.0 はコンテキスト長256kトークンと記載されています。TypeSafe では、長いコンテキストを使うためにオプトイン用のリクエストヘッダー TypeSafe-Danger-Zone-Long-Context: true が必要です。AnyAIGC はこのヘッダーをそのまま転送します。また TypeSafe は、無関係な state が大量にあると精度が下がると述べているので、可能であれば長い入力は分割してください。

jev-1.14.0 に画像を送るにはどうしますか？

画像を Base64 にして assets オブジェクトに入れ（{"type": "image", "format": "png", "data_base64": "..."}）、state からそのプレースホルダーを参照し、ヘッダー TypeSafe-Danger-Zone-Images: true を追加します。TypeSafe によると、画像は PNG または JPEG で、16 MiB 以下、1辺280〜1568 px である必要があり、通常の入力トークンとして課金されます。画像入力は実験的機能で、TypeSafe は本番環境ではまだ推奨していません。

box 質問タイプとは何ですか？

box は実験的な質問タイプで、jev-1.14.0 だけが対応しています。画像アセット内の物体の位置を特定するもので、ヘッダー TypeSafe-Danger-Zone-Images: true が必要です。TypeSafe のドキュメントによると、答えには物体の上端、下端、左端、右端が0〜1の割合で含まれ、さらに null になりうる信頼度が付きます。物体が存在するかどうかを確認する noul 質問と組み合わせてください。

jev-1.14.0 API は OpenAI 互換ですか？

いいえ。Jev は TypeSafe の System One インターフェースを使います。POST https://anyaigc.ai/v1/systemone に model、state、questions、任意の assets を送ると、answers と usage が返ります。messages や choices はないため、OpenAI SDK では呼び出せません。requests、fetch、cURL などで通常の HTTP リクエストを送り、ヘッダー Authorization: Bearer <API Key> を付けてください。呼び出しは同期で、ストリーミングやタスクのポーリングはありません。

jev-1.14.0 の速度はどのくらいですか？

TypeSafe によると、エンドツーエンドの応答時間は70〜500 msです。TypeSafe は自社のワークフロー評価で、Jev は LLM より193.6倍高速で444.6倍低コストと報告していますが、これは高めの水準だとしています。1回のリクエスト内の質問はすべて並列で処理され、AnyAIGC は同時実行数に上限を設けていません。これらの数値に頼る前に、自分のワークロードで測定してください。

jev-1.14.0 はどの言語に対応していますか？

英語が最も得意です。他の言語も使え、TypeSafe によると 1.14 の主な改善点は多言語の品質です。第三者の論文では、jev-1.13.0 は122言語の Belebele で86.7%と測定され、低リソース言語ではより弱いことが示されています。本番に出す前に、各言語の自分のサンプルでテストしてください。

jev-1.14.0 の制限事項は何ですか？

TypeSafe によると、Jev は書かれた表現を文字どおりに解釈します。数学や数え上げには向きません（「Jev は電卓ではありません」）。日付の比較やマルチホップの質問は苦手です。無関係な state が大きいと精度が下がります。プロンプトインジェクションのリスクがあります。choice の質問では最初の選択肢がわずかに選ばれやすくなります。そして、テキストは生成しません。コードで計算できるものはコードで計算し、1つの質問では1つのことだけを尋ねてください。

jev-1.14.0 は商用利用できますか？

TypeSafe の公式規約に従う限り、自社のプロダクトや業務ワークフローから呼び出せます。TypeSafe は、顧客データで学習しないとしています。

jev-1.14.0 の APIキーはどう取得しますか？

anyaigc.ai で登録してチャージし、コンソールでトークンを作成して、sk- で始まるキーをコピーします。キーは環境変数 ANYAIGC_API_KEY に保存してください。同じキーで、jev-1.14.0、jev-1.13.0、プラットフォーム上の300以上の他のモデルを呼び出せます。

AnyAIGC で請求書を発行できますか？

はい。実際にチャージした金額分の請求書を、コンソールでご自身で発行できます。

対応している支払い方法は何ですか？

WeChat Pay、Alipay、USDT、クレジットカードでチャージできます。残高は USD で、プラットフォーム上のすべてのモデルで使えます。チャージした金額分の請求書は、コンソールで発行できます。

新規ユーザー向けの無料トライアルはありますか？

はい。新規アカウントには200万トークン分のトライアル枠が付与されるので、チャージするかどうか決める前に試せます。チャージは $1 から可能です。

残高は返金できますか？

はい。未使用の残高は手数料なしで返金できます。返金をご希望の場合は、サポートにご連絡ください。

本物のモデルですか？データは安全ですか？

リクエストは公式のモデルチャネルに送られ、安価な代替モデルやリバースエンジニアリングによるモデルは使いません。法令で求められる場合を除き、プロンプトや出力を永続的に保存せず、学習にも使用しません。コンソールでは、リクエストごとのトークン数と料金を確認できます。
