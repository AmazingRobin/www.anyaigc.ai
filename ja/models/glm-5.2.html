概要

長時間タスク向けに作られた、コンテキスト長1Mのフラッグシップ

Zhipu は GLM-5.2 を、長時間タスクの時代に向けたフラッグシップと位置づけています。Zhipu によると、コンテキスト長1Mは実用的に使え、プロジェクト規模のエンジニアリングのコンテキストに対応します。また、長いタスクをより安定して実行し、エンジニアリング規約をより一貫して守ります。

コンテキスト長は GLM-5.1 の200Kから1Mに拡大しました。アーキテクチャは MoE と DSA スパースアテンションを引き継ぎ、IndexShare を追加しています。これは4つのスパースアテンション層ごとに1つのインデクサーを共有する仕組みで、Zhipu によると、コンテキスト長1Mでのトークンあたりの計算量を2.9倍削減します。GLM-5.2 はデフォルトでダイナミックな思考モードを使い、思考モードはオフにできます。MIT ライセンスのオープンソースです。

AnyAIGC では、glm-5.2 は OpenAI 互換の /v1/chat/completions エンドポイントで動作し、Claude Code でもそのまま使え、同時実行数に上限はありません。新規プロジェクトには、同じ料金の GLM-5.3 もご検討ください。同じベースモデルを基に、コーディング性能を強化したモデルです。

クイックスタート

3ステップで GLM-5.2 API に接続

  1. 登録とチャージ：anyaigc.ai でアカウントを作成します。$1からチャージでき、残高はプラットフォーム上のすべてのモデルで使えます。
  2. APIキーを作成：コンソールでキーを作成し、sk- で始まる値をコピーして、環境変数 ANYAIGC_API_KEY に保存します。
  3. リクエストを送信：POST https://anyaigc.ai/v1/chat/completions を呼び出し、model に glm-5.2 を指定して、Authorization: Bearer ヘッダーを付けます。OpenAI SDK を使う場合は、base_url を https://anyaigc.ai/v1 に設定するだけです。

ヒント：GLM-5.2 はデフォルトでダイナミックな思考モードを使います。推論がある場合は reasoning_content フィールドで返され、reasoning_effort で深さを指定できます。マルチターンの会話やツール呼び出しでは、API から返ったアシスタントメッセージ全体（reasoning_content と tool_calls を含む）を、変更せずに次のリクエストへ送り返してください。

全パラメータは Chat Completions リファレンスをご覧ください。ドキュメントの例にあるモデル名は、使いたい GLM のモデルIDに置き換えてください。

Claude Code

Claude Code で GLM-5.2 を使う

Claude Code を GLM-5.2 に切り替えます。コンテキスト長1Mは、大規模リポジトリでの長いコーディングセッションに向いています。

  1. Claude Code をインストール：公式インストーラーを使います。macOS または Linux の場合は、たとえば curl -fsSL https://claude.ai/install.sh | bash です。
  2. 設定を追加：~/.claude/settings.json を編集し、下の env ブロックを追加して、ANTHROPIC_AUTH_TOKEN を AnyAIGC で作成したキーに置き換えます。
  3. コーディングを開始：プロジェクトのフォルダで claude を実行し、/model と入力して、現在のモデルが glm-5.2 であることを確認します。

アップグレードのヒント：コーディングの成功率を上げたい場合は、設定内のすべての glm-5.2 を glm-5.3 に置き換えてください。料金は同じです。

手順の全体とよくあるエラーは、Claude Code の設定ガイドをご覧ください。ガイド内のモデル名は glm-5.2 に置き換えてください。

仕様と選び方

Z.ai のドキュメントは、GLM-5.2 を長時間タスク向けに作られたフラッグシップモデルと説明し、1Mトークンのコンテキスト長が実際に使えることを強調しています。

ベンダーによると、長時間のコーディングエージェント向けシナリオ（大規模な実装、自動化されたリサーチ、パフォーマンス最適化）に向けて、数か月にわたる専門的なトレーニングを行っています。

ベンダーによると、GLM-5.3 は同じベースモデルを使い、改善はポストトレーニングによるものです。

このページでは入力$0.9450、出力$2.9700、キャッシュヒット$0.2362を掲載しており、上の料金表と一致します。

glm-5.3 との比較：ベンダーによると、GLM-5.3 は Z.ai Code Bench で GLM-5.2 より50%向上しているため、より強いコーディングとエージェント性能が必要な場合に選んでください。

FAQ

GLM-5.2 API よくある質問

GLM-5.2 API の料金はいくらですか？

AnyAIGC では glm-5.2 はトークン単位で課金されます。入力は100万トークンあたり$0.9450、出力は100万トークンあたり$2.9700、キャッシュヒットは100万トークンあたり$0.2362です。Zhipu の公式の定価（USD）は入力$1.40、出力$4.40、キャッシュヒット$0.26で、AnyAIGC の入力と出力は定価の約67.5%（約30%オフ）です。最新の料金はモデル一覧でご確認ください。

GLM-5.2 のモデルIDは何ですか？コンテキスト長はどのくらいですか？

モデルIDは glm-5.2 です。Zhipu は、コンテキスト長1M、最大128Kトークンの出力と公表しています。入力はテキストのみです。

GLM-5.2 で思考モードをオフにできますか？

はい。Zhipu によると、GLM-5.2 はデフォルトでダイナミックな思考モードを使い、思考するかどうかをモデルが判断します。思考モードはオフにもできます。これが、常に思考する GLM-5.3 との主な違いの1つです。AnyAIGC では reasoning_effort で思考の深さを指定できます。

GLM-5.2 の特長は何ですか？

Zhipu positioniert GLM-5.2 als Flaggschiff für die Ära langlaufender Aufgaben. Das 1M-Kontextfenster ist in der Praxis nutzbar und reicht für Engineering-Kontext im Projektmaßstab. Das Modell führt lange Aufgaben zuverlässiger aus, hält Engineering-Konventionen konsistenter ein und kann eine Aufgabe von den Anforderungen bis zum Multi-Plattform-Deployment begleiten. Laut Zhipu senkt das IndexShare-Design den Rechenaufwand pro Token bei 1M Kontext um den Faktor 2,9.

GLM-5.2 と GLM-5.3 のどちらを使うべきですか？

Beide teilen dasselbe Basismodell und kosten bei AnyAIGC für Eingabe und Ausgabe gleich viel. GLM-5.3 ergänzt ein hochskaliertes Post-Training; Zhipu berichtet 50 % bessere Coding-Leistung, und der Preis für Cache-Treffer ist niedriger ($0,1758 statt $0,2362). Neue Projekte sollten mit GLM-5.3 starten. Bleiben Sie bei GLM-5.2, wenn Sie den Denkmodus abschalten müssen oder es bereits produktiv abgestimmt haben.

GLM-5.2 を Claude Code で使えますか？

はい。~/.claude/settings.json の env ブロックで、ANTHROPIC_BASE_URL に https://anyaigc.ai、ANTHROPIC_AUTH_TOKEN に APIキー、ANTHROPIC_MODEL に glm-5.2 を設定し、claude を実行します。課金はトークン単位で、サブスクリプションプランのような5時間のクォータ枠はありません。

Ist GLM-5.2 Open Source? Darf ich es kommerziell nutzen?

はい。Zhipu は GLM-5.2 のウェイトを MIT ライセンスで Hugging Face（zai-org/GLM-5.2）と ModelScope に公開しています。AnyAIGC 経由で API を呼び出せば、自分でホストする必要はありません。商用利用は Zhipu AI の公式規約に従います。

同時実行数やレート制限はありますか？

AnyAIGC begrenzt die Parallelität für glm-5.2 nicht, und jeder Nutzer erhält das standardmäßig. Das passt zu Batch-Jobs, CI-Pipelines und parallelen Agenten. Die Abrechnung erfolgt pro Token, es gibt also kein Kontingent, das sich wie bei einem Abo-Tarif nach einem Zeitfenster zurücksetzt.

GLM-5.2 の APIキーはどうやって取得しますか？

anyaigc.ai で登録し、チャージして、コンソールでキーを作成します。同じキーで、すべての GLM モデルとプラットフォーム上の300以上のモデルを利用できます。Zhipu のプラットフォームのアカウントや GLM Coding Plan は別途必要ありません。

AnyAIGC で請求書を発行できますか？

はい。実際にチャージした金額分の請求書を、コンソールでご自身で発行できます。

対応している支払い方法は何ですか？

WeChat Pay、Alipay、USDT、クレジットカードでチャージできます。残高は USD で、プラットフォーム上のすべてのモデルで使えます。チャージした金額分の請求書は、コンソールで発行できます。

新規ユーザー向けの無料トライアルはありますか？

はい。新規アカウントには500万トークン分のトライアル枠が付与されるので、チャージするかどうか決める前に試せます。チャージは $1 から可能です。

残高は返金できますか？

はい。未使用の残高は手数料なしで返金できます。返金をご希望の場合は、サポートにご連絡ください。

本物のモデルですか？データは安全ですか？

リクエストは公式のモデルチャネルに送られ、安価な代替モデルやリバースエンジニアリングによるモデルは使いません。法令で求められる場合を除き、プロンプトや出力を永続的に保存せず、学習にも使用しません。コンソールでは、リクエストごとのトークン数と料金を確認できます。
