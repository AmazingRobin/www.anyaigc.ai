01 · Jev とは

Jev とは：段落ではなく、判定を返すモデル

チャット LLM が返すのは、あとから解析が必要なテキストです。Jev がコードに返すのは、そのまま使える値（確率、選択肢、スコア）です。

Jev は TypeSafe AI 初の公開 System One モデルです。名前は、ダニエル・カーネマンの「System 1」（熟考せずに脳が下す、速くて直感的な判断）に由来します。TypeSafe によると、Jev は RLCD（Reinforcement Learning for Calibrated Decisions）と並列サンプラーで学習されており、自由なテキストではなく、較正済みの確率を伴う型付きの回答を返します。

賢い if 文だと考えてください。判定したい内容を state に入れ、名前と型を持つ質問を questions に定義すると、すべての質問が1回のリクエストで並列に回答されます。質問数に上限はありません。TypeSafe は、回答が指定した型とスキーマに一致することを保証しているため、解析やリトライのロジックを書く必要はありません。

02 · 質問タイプ

4種類の質問タイプ：noul、choice、score、box

questions で各質問に名前を付けると、回答は同じ名前で返ってきます。

  • type: noul

    noultrue の確率

    ある事柄が真である可能性はどのくらいか。0から1の確率を返します。instructions で質問するか、criteria で true と false を記述します。

    リクエスト 
    "is_urgent": {
  "type": "noul",
  "instructions": "Does this convey urgency?"
}
    回答 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice選択肢から1つを選ぶ

    criteria は選択肢名から説明へのマッピングで、選択肢は1〜255個です。選ばれた選択肢、信頼度、各選択肢の確率を返します。

    リクエスト 
    "department": {
  "type": "choice",
  "criteria": {"billing": "…", "sales": "…", "technical": "…"}
}
    回答 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score段階で評価する

    criteria は2〜10段階の順序付き配列です。確率で重み付けしたスコア（小数になることがあります）、信頼度、凡例、各段階の確率を返します。

    リクエスト 
    "frustration": {
  "type": "score",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
    回答 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · jev-1.14.0

    box画像内のオブジェクトの位置を特定 実験的

    jev-1.14.0 のみ対応しています。assets に画像を入れ、ヘッダー TypeSafe-Danger-Zone-Images: true が必要です。TypeSafe のドキュメントによると、回答にはオブジェクトの上・下・左・右の端が0〜1の割合で含まれ、null になる場合がある信頼度も付きます。

    リクエスト 
    "mug": {
  "type": "box",
  "instructions": "the coffee mug in `photo`"
}
    注意 
    # Full example below in "Images & box"

05 · ユースケース

Jev の主な用途

コードが分岐、並べ替え、アラートに使える結果を必要とする場面で使えます。

  • 01 · choice

    分類とインテント

    メッセージ、商品、ドキュメントを固定のカテゴリに振り分け、それぞれに確率を付けます。確信度の低いものは人間または LLM に回せます。

  • 02 · choice + noul

    チケットのルーティング

    1回のリクエストで、担当チーム、緊急度、不満の度合いを判定します。チケットを誰が受け持ち、キューのどこに置くかがわかります。

  • 03 · score

    リスクスコアリング

    取引、ドキュメント、アカウントを独自の基準でスコアリングします。スコアは確率で重み付けした小数なので、しきい値を設定しやすくなります。

  • 04 · noul

    コンテンツモデレーション

    コメントやユーザー生成コンテンツのポリシー違反を確認します。ポリシーのルールごとに1つの質問とし、並列に回答します。

  • 05 · noul

    LLM ガードレール

    LLM の前後にチェックを追加します。ジェイルブレイクやプロンプトインジェクションを検出し、出力が提供したソースの範囲に収まっているかを検証します。

  • 06 · score

    採点と評価

    応答を尺度でスコアリングし、入力分のみの費用で、LLM-as-judge の一部を代替できます。第三者の論文では、ルーブリック形式の品質判定は苦手とされているため、頼る前にサンプルを確認してください。

  • 07 · if

    賢い if 文

    テキストから条件を抽出します。返金リクエストか、競合他社に言及しているか、顧客が折り返しを希望しているか。その回答をそのままビジネスロジックにつなげます。

  • 08 · map-reduce

    大規模データセットのバッチ処理

    何百万件ものレコードを1件ずつラベル付けして、結果を集計します。同時実行数の上限なしと出力無料は、オフラインのバッチ処理に向いています。

  • 09 · リアルタイム

    リアルタイムアプリ

    TypeSafe によると、典型的なレスポンスは約100 ms で、ユーザー向けのリクエスト経路に組み込めるほど高速です。

07 · 制限事項

本番投入の前に知っておきたい Jev の制約

TypeSafe の公式ガイダンスに基づく内容です。コードで計算できることはコードに任せ、1つの質問では1つのことだけを尋ねてください。

  • 文字どおりに解釈意図した質問ではなく、書かれた質問に答えます。正確な言葉で書いてください。
  • 計算機ではありません計算や数え上げは避け、そのロジックはコードで処理してください。
  • 日付と多段推論日付の比較や複数ステップの推論は、分解してから Jev に質問してください。
  • 無関係な state は逆効果無関係な内容が大量にあると精度が下がります。判定が必要なものだけを送ってください。
  • プロンプトインジェクションstate に信頼できない内容が含まれると、答えが左右されるおそれがあります。重要な場面では対策を追加してください。
  • 最初の選択肢への偏りchoice の質問は、最初の選択肢にわずかに偏ります。順序をシャッフルして確認してください。
  • テキスト生成は不可チャット、要約、書き換えはできません。文章が必要な場合は LLM と組み合わせてください。
  • 英語優先英語が最も良好です。他の言語でも動作しますが、精度は下がります。

09 · クイックスタート

3ステップで Jev API に接続

Jev は OpenAI 互換ではありません。通常の HTTP リクエストで /v1/systemone を呼び出してください。

  1. 登録とチャージ：anyaigc.ai でアカウントを作成します。残高はすべてのモデルで共通です。
  2. APIキーの作成：コンソールでトークンを作成し、sk- で始まるキーをコピーして、環境変数 ANYAIGC_API_KEY に保存します。
  3. リクエストを送信：https://anyaigc.ai/v1/systemone に POST し、model に jev-1.14.0 を指定して、state と questions を渡します。レスポンスは同期で返るため、ポーリングは不要です。全フィールドは API ドキュメントを参照してください。

英語が最適です。TypeSafe によると、Jev は英語が最も得意です。他の言語でも動作しますが、精度は下がります。コンテンツが他の言語の場合は、instructions と criteria を英語のままにし、本番投入の前に自分のサンプルでしきい値をテストしてください。

レスポンスの値は AnyAIGC API ドキュメントに基づいています。model には実際に実行されたバージョンが入り、usage.output_tokens は課金されません。不正なボディは 400、不正なキーは 401 を返し、エラーボディは {"error": {"code", "message", "param", "type"}} の形式です。パラメータの詳細は AnyAIGC System One API ドキュメントにあります。

10 · 画像 & box

jev-1.14.0 の画像入力と box による位置特定

画像を Base64 エンコードして assets に入れ、state からそのプレースホルダーを参照し、ヘッダーを1つ追加します。

実験的機能です。TypeSafe のドキュメントによると、画像は PNG または JPEG で、16 MiB 以下、1辺 280〜1568 px で、通常の入力トークンとして課金されます。リクエストには TypeSafe-Danger-Zone-Images: true を含める必要があります。TypeSafe は、画像と box はまだ本番利用を推奨しないとしています。256k の長いコンテキストにも、ヘッダー TypeSafe-Danger-Zone-Long-Context: true が必要です。AnyAIGC はこれらのヘッダーと assets をそのまま渡します。

box は位置を特定するだけです。この例では noul の質問を追加し、box を信用する前に、そもそも画像にそのオブジェクトがあるかを確認しています。プレースホルダーは単なる文字列なので、実際のテキストと衝突しないよう、画像ごとに新しいランダムな ID を使ってください。

FAQ

Jev API のよくある質問

Jev とは？

Jev は TypeSafe AI が初めて公開した System One モデルです。名前はダニエル・カーネマンの「System 1」、つまり速く直感的な判断に由来します。判断したい内容（state）と型付きの質問（questions）を送ると、較正された確率を伴う型付きの回答を返します。たとえば、どのカテゴリに属するか、ある文がどれくらい真らしいか、尺度上のどこに位置するか、といった回答です。TypeSafe によると、Jev は RLCD（Reinforcement Learning for Calibrated Decisions）と並列サンプラーで学習されています。

Jev はテキストを生成しますか？チャットモデルとして使えますか？

いいえ。Jev はテキストを生成せず、チャット、補完、要約の機能もありません。定義した質問にだけ答え、すべての回答は要求した型（確率、選択肢、スコア）に一致します。文章の作成には同じプラットフォームの GPT や Claude などの LLM を使い、分類、ルーティング、モデレーション、スコアリングに Jev を使ってください。

Jev API は OpenAI 互換ですか？OpenAI SDK は使えますか？

いいえ。Jev は TypeSafe 独自の System One インターフェースを使います。POST https://anyaigc.ai/v1/systemone に model、state、questions（画像の場合は assets も）を含むボディを送ります。レスポンスは answers と usage で、messages や choices はありません。OpenAI SDK からは呼び出せないため、requests、fetch、cURL で通常の HTTP リクエストを送ってください。認証は従来どおり Authorization: Bearer <API Key> です。エンドポイントは同期式で、ストリーミングもタスクのポーリングもありません。

Jev API の料金は？出力は本当に無料ですか？

AnyAIGC では jev-1.14.0 と jev-1.13.0 は同じ料金で、入力100万トークンあたり$0.0227、出力は無料です。トークン単位の従量課金で、課金されるのは入力トークンだけです。画像は通常の入力トークンとして課金されます。たとえば、入力300トークンのリクエストを1,000,000件送ると300Mトークンとなり、料金は$6.81です。同時実行数はすべてのユーザーで上限なしです。最新の料金は AnyAIGC のモデル一覧で確認できます。

jev-1.14.0 と jev-1.13.0 の違いは？

jev-1.13.0 は2026年9月15日にリリースされた最初の公開バージョンで、コンテキスト長は32kトークンです。jev-1.14.0 は2026年10月14日にリリースされました。TypeSafe は、全体的に小さな改善があり、特に多言語性能の向上が大きいと説明しています。AnyAIGC ではコンテキスト長256kに対応し、実験的な画像入力と box 質問タイプが加わっています。料金は同じで、新規プロジェクトには jev-1.14.0 をおすすめします。

Jev のコンテキスト長は？

AnyAIGC のモデル一覧によると、jev-1.13.0 のコンテキスト長は32kトークン、jev-1.14.0 は256kトークンです。TypeSafe のドキュメントでは、長いコンテキストを使うにはリクエストヘッダー TypeSafe-Danger-Zone-Long-Context: true が必要で、AnyAIGC はこのヘッダーをそのまま転送します。また TypeSafe は、長いコンテキストはデフォルトの長さより遅く、精度も下がると注記しています。可能な場合は内容を分割してください。

Jev は画像を扱えますか？box 質問タイプとは？

jev-1.14.0 は実験的な画像入力に対応しています。base64 エンコードした PNG または JPEG をリクエストボディの assets に入れ（最大16 MiB、1辺280〜1568 px）、state からそのプレースホルダーを参照し、ヘッダー TypeSafe-Danger-Zone-Images: true を送ります。box は 1.14 で追加された実験的な質問タイプで、画像内のオブジェクトの位置を特定するために使い、同じヘッダーと画像が必要です。画像は通常の入力トークンとして課金されます。TypeSafe は、画像機能はまだ本番利用には推奨されないとしています。

Jev が対応する言語は？

英語での精度が最も高くなります。TypeSafe によると、他の言語でも動作しますが精度は下がり、jev-1.14.0 は 1.13 より多言語性能が向上しています。第三者の論文では、jev-1.13.0 は122言語にわたる Belebele で86.7%の精度を記録し、低リソース言語では結果が弱くなっています。精度が重要な場合は、質問を英語で書き、本番投入の前に自分のサンプルでテストしてください。

Jev の制限は？

TypeSafe によると、Jev は書かれた表現を文字どおりに解釈します。数学や数え上げには向きません（「Jev は電卓ではありません」）。日付の比較やマルチホップの質問は苦手です。無関係な state が多いと精度が下がります。プロンプトインジェクションのリスクがあります。choice の質問では最初の選択肢にわずかに偏る傾向があります。そして、テキストは生成できません。コードで計算できることはコードで計算し、1つの質問では1つのことだけを聞いてください。

Jev は商用利用できますか？

Jev は自社の製品や業務ワークフローから呼び出せます。商用利用は TypeSafe の公式規約に従います。TypeSafe は、顧客データで学習しないとしています。

Jev の APIキーを取得するには？

anyaigc.ai で登録してチャージし、コンソールでトークンを作成して、sk- で始まるキーをコピーし、環境変数 ANYAIGC_API_KEY に保存します。同じキーで jev-1.14.0、jev-1.13.0、およびプラットフォーム上の300以上の他のモデルを利用できます。

WeChat Pay、Alipay、USDT、クレジットカードでチャージできます。残高は USD で、プラットフォーム上のすべてのモデルで使えます。チャージした金額分の請求書は、コンソールで発行できます。

新規ユーザー向けの無料トライアルはありますか？

本物のモデルですか？データは安全ですか？

リクエストは公式のモデルチャネルに送られ、安価な代替モデルやリバースエンジニアリングによるモデルは使いません。法令で求められる場合を除き、プロンプトや出力を永続的に保存せず、学習にも使用しません。コンソールでは、リクエストごとのトークン数と料金を確認できます。
