01 · WHAT'S NEW

Jev 1.14 有什么新变化

按 TypeSafe 的发布说明，1.14 在各方面都有小幅提升，多语言提升最明显，并带来三项新能力。

  • multilingual

    多语言更好

    TypeSafe 称这是 1.14 提升最明显的地方。英文仍然最好，中文和其他语言的判断比 1.13 更稳。

  • 256k

    256k 上下文

    AnyAIGC 模型广场标注 jev-1.14.0 上下文 256k tokens（1.13 为 32k）。长上下文需要加请求头 TypeSafe-Danger-Zone-Long-Context: true。

    图片输入（实验性）

    在 assets 里放 PNG 或 JPEG，在 state 里引用，就能对图片提问。需要请求头 TypeSafe-Danger-Zone-Images: true。

  • box

    Box 问题类型（实验性）

    1.14 独有的新题型，用来在图片里定位目标，返回目标的边界位置。同样需要图片请求头和一张图片。

  • same API

    接口不变

    请求格式和 1.13 一样，还是 model、state、questions。升级只需要把模型名改成 jev-1.14.0。

  • same price

    价格不变

    在 AnyAIGC 上和 1.13 同价：输入 $0.0227 / 百万 tokens，输出免费，所有用户默认不限并发。

TypeSafe 没有公布 1.14 相对 1.13 的具体提升幅度。图片和 Box 属于 TypeSafe 所说的实验性功能，目前还不建议用于生产环境。

02 · QUESTION TYPES

jev-1.14.0 支持的四种问题类型

Jev 不生成文字，只回答你定义的问题。一次请求里所有问题并行作答，数量不设上限，答案一定符合你要求的类型。

  • type: noul

    noul是或否的概率

    判断一件事有多大可能为真，返回 0–1 的概率。用 instructions 提问，或用 criteria 分别描述 true 和 false。

    答案 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice从选项里选一个

    criteria 写成「选项名 → 描述」，支持 1 到 255 个选项。返回选中的项、置信度和每个选项的概率。

    答案 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score按量表打分

    criteria 是一个有序数组，2 到 10 级。返回按概率加权的分数（可以是小数）、置信度、各级说明和概率。

    答案 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · 1.14 新增

    box在图片里定位目标 实验性

    仅 jev-1.14.0 支持，需要一张图片和请求头 TypeSafe-Danger-Zone-Images: true。按 TypeSafe 文档，答案给出目标的上（top）、下（bottom）、左（left）、右（right）边界，取值为 0–1 的比例，另有 confidence（可能为 null）。

    请求 
    "mug": {
  "type": "box",
  "instructions": "the coffee mug in `photo`"
}

06 · QUICKSTART

三步接入 jev-1.14.0 API

Jev 不兼容 OpenAI 接口，没有 messages 和 choices，OpenAI SDK 不能直接调用。用普通 HTTP 请求调用 /v1/systemone。

  1. 注册并充值：在 anyaigc.ai 注册账号，余额对平台所有模型通用。
  2. 创建 API Key：在控制台创建令牌，复制以 sk- 开头的 Key，存到环境变量 ANYAIGC_API_KEY。
  3. 发起请求：向 https://anyaigc.ai/v1/systemone 发送 POST，model 填 jev-1.14.0，带上 state 和 questions。接口同步返回，不需要轮询。

中文业务的写法建议。TypeSafe 称英文效果最好，1.14 的中文比 1.13 有提升，但仍弱于英文。可以把待判断的中文内容原样放进 state，把 instructions 和 criteria 写成英文，上线前用自己的样本测一遍阈值。

返回示例的数值取自 AnyAIGC 接口文档，实际结果以你的请求为准。model 返回实际运行的版本；usage.output_tokens 不计费。请求体格式错误返回 400，Key 无效返回 401，错误体格式为 {"error": {"code", "message", "param", "type"}}。完整参数见 AnyAIGC System One 接口文档。

07 · LONG CONTEXT · IMAGES · BOX

长上下文、图片输入与 Box 定位

这三项是 jev-1.14.0 的新能力，都要在请求头里显式开启。AnyAIGC 会透传这些请求头和 assets。

256k 长上下文

请求头加 TypeSafe-Danger-Zone-Long-Context: true。TypeSafe 提醒长上下文比默认长度更慢、准确率更低；state 里无关内容越多越容易出错，能切分的尽量切分。

图片 · Box

请求头加 TypeSafe-Danger-Zone-Images: true。按 TypeSafe 文档，图片支持 PNG 和 JPEG，单张不超过 16 MiB，每边 280–1568 像素，按普通输入 tokens 计费。

实验性功能。TypeSafe 称图片和 Box 目前还不建议用于生产环境。适合先做原型和内部工具，并为 Box 结果加上人工或规则校验。

Box 只负责定位，示例里另用一个 noul 问题判断图里是否有目标，再决定是否使用 Box 的结果。占位符只是普通字符串，建议每张图用一个新的随机 ID，避免和正文里的文字撞上。长上下文请求同理，把请求头换成 TypeSafe-Danger-Zone-Long-Context: true。

FAQ

jev-1.14.0 API 常见问题

jev-1.14.0 是什么？

jev-1.14.0 是 TypeSafe AI 于 2026 年 10 月 14 日发布的 Jev 最新版本。Jev 是第一款公开的 System One 模型，不生成文字，而是对你定义的问题返回带校准概率的类型化答案（概率、选项、分数或图片中的位置）。TypeSafe 称 1.14 各方面都有小幅提升，多语言提升最明显，并新增实验性的图片输入和 Box 问题类型；在 AnyAIGC 上开放 256k 上下文。

jev-1.14.0 和 jev-1.13.0 有什么区别？

接口和价格都一样。区别在于：jev-1.14.0 上下文 256k tokens（1.13 为 32k），多语言能力更好，支持实验性的图片输入和 Box 问题类型；jev-1.13.0 是 2026 年 9 月 15 日发布的第一个公开版本，只支持文本和 noul、choice、score 三种问题类型。TypeSafe 没有公布 1.14 相对 1.13 的具体提升幅度。

已经在用 jev-1.13.0，应该升级到 1.14 吗？

新项目建议直接用 jev-1.14.0。存量业务升级只需要把 model 改成 jev-1.14.0，请求体和价格都不变。如果你在 1.13 上按概率调好了阈值，建议先用自己的样本同时跑两个版本，确认结果后再切换；需要长上下文、图片、Box 或非英文内容的业务升级收益更明显。

jev-1.14.0 API 多少钱？

AnyAIGC 上 jev-1.14.0 输入 $0.0227 / 百万 tokens，输出免费，按量计费，只收输入 tokens，图片和长上下文都按输入 tokens 计。例如 100 万次请求、每次 300 个输入 tokens，共 3 亿 tokens，费用是 $6.81。所有用户默认不限并发。实时价格以 AnyAIGC 模型广场为准。

jev-1.14.0 的 256k 长上下文怎么开启？

按 TypeSafe 的文档，长上下文需要在请求头里加 TypeSafe-Danger-Zone-Long-Context: true，AnyAIGC 会透传这个请求头。TypeSafe 提醒长上下文比默认长度更慢、准确率更低，state 里无关内容太多也会降低准确率，能切分的内容尽量切分后再判断。

jev-1.14.0 怎么输入图片？

在请求体 assets 里放 base64 编码的图片（{"type": "image", "format": "png", "data_base64": "..."}），在 state 里引用它的占位符，并加请求头 TypeSafe-Danger-Zone-Images: true。按 TypeSafe 文档，图片支持 PNG 和 JPEG，单张不超过 16 MiB，每边 280–1568 像素，按普通输入 tokens 计费。图片输入是实验性功能，TypeSafe 称目前还不建议用于生产环境。

Box 问题类型是什么？返回什么？

Box 是 1.14 新增的实验性问题类型，用来在图片里定位目标，只有 jev-1.14.0 支持，需要一张图片和图片请求头。按 TypeSafe 文档，答案给出目标的上（top）、下（bottom）、左（left）、右（right）边界，取值为 0–1 的比例，另有 confidence（可能为 null）。建议另用一个 noul 问题先判断图里是否有目标。

jev-1.14.0 支持中文吗？

支持，但英文效果最好。TypeSafe 称 1.14 的多语言提升是这一版最明显的改进，中文等其他语言比 1.13 更稳，但仍弱于英文。第三方论文在 122 种语言的 Belebele 上测得 jev-1.13.0 准确率 86.7%，低资源语言偏弱。对准确率要求高的场景，建议把 instructions 和 criteria 写成英文，并先用自己的中文样本测试再上线。

jev-1.14.0 兼容 OpenAI 接口吗？

不兼容。Jev 使用 TypeSafe 自己的 System One 接口：POST https://anyaigc.ai/v1/systemone，请求体是 model、state、questions（图片再加 assets），返回 answers 和 usage，没有 messages 和 choices。OpenAI SDK 不能直接调用，请用 requests、fetch 或 cURL 发普通 HTTP 请求，鉴权是 Authorization: Bearer <API Key>。接口是同步的，没有流式输出，也不需要轮询任务。

jev-1.14.0 有哪些局限？

按 TypeSafe 官方说明：Jev 按字面理解问题；不擅长数学和计数（「Jev 不是计算器」），也不擅长日期比较和多跳推理；state 里无关内容太多会降低准确率；有提示注入风险；choice 问题对第一个选项略有偏好；不能生成文字。图片和 Box 属于实验性功能。能用代码算出来的东西就用代码，一个问题只问一件事。
