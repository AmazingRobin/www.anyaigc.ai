01 · WHAT IS JEV-1.13.0

jev-1.13.0：第一个公开的 System One 模型

聊天大模型给你一段话，你还得再解析。jev-1.13.0 直接给程序能用的值：一个概率、一个选项或一个分数。

TypeSafe AI 在 2026 年 9 月 15 日发布了 jev-1.13.0，这是第一款公开的 System One 模型。System One 来自卡尼曼说的「系统 1」，也就是人脑里快速、直觉式的判断。TypeSafe 称 Jev 用 RLCD（Reinforcement Learning for Calibrated Decisions，面向校准决策的强化学习）和并行采样器训练，输出不是自由文本，而是带校准概率的类型化答案。

用法很像写一个「聪明的 if 语句」：把要判断的内容放进 state，在 questions 里定义若干个带名字、带类型的问题，一次请求里所有问题并行作答，数量不设上限。TypeSafe 保证答案一定符合你要求的类型和结构，不需要再写解析和重试逻辑。

02 · QUESTION TYPES

jev-1.13.0 支持的三种问题类型

每个问题在 questions 里起一个名字，答案按同样的名字返回。

  • type: noul

    noul是或否的概率

    判断一件事有多大可能为真，返回 0–1 的概率。用 instructions 提问，或用 criteria 分别描述 true 和 false。

    请求 
    "is_urgent": {
  "type": "noul",
  "instructions": "Does this convey urgency?"
}
    答案 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice从选项里选一个

    criteria 写成「选项名 → 描述」，支持 1 到 255 个选项。返回选中的项、置信度和每个选项的概率。

    请求 
    "department": {
  "type": "choice",
  "criteria": {"billing": "…", "sales": "…", "technical": "…"}
}
    答案 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score按量表打分

    criteria 是一个有序数组，2 到 10 级。返回按概率加权的分数（可以是小数）、置信度、各级说明和概率。

    请求 
    "frustration": {
  "type": "score",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
    答案 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • 需要图片或 box？

    jev-1.14.0256k 上下文 · 图片 · box

    在 AnyAIGC 上，jev-1.13.0 为文本输入、32k 上下文，不支持 box。在图片里定位目标的实验性 box 类型、图片输入和 256k 上下文都在 jev-1.14.0 上，价格相同。

04 · USE CASES

jev-1.13.0 适合做什么

需要程序直接拿结果去分支、排序或报警的地方，都可以交给 Jev。

  • 01 · choice

    分类与意图识别

    把用户消息、商品、文档分到固定类别，拿到每个类别的概率，低置信度的再交给人工或大模型。

  • 02 · choice + noul

    工单路由

    一次请求同时判断归属团队、是否紧急、情绪强度，直接决定派给谁、排在第几位。

  • 03 · score

    风险打分

    按你写的分级标准给交易、单据、账户打分，分数是按概率加权的小数，方便设阈值。

  • 04 · noul

    内容审核

    对评论、弹幕、用户生成内容做违规判断，多条规则写成多个问题并行作答。

  • 05 · noul

    大模型护栏

    在大模型前后各加一道检查：识别越狱和提示注入、核对输出是否引用了给定资料。

    评审与打分

    代替一部分「LLM 当裁判」的评测任务，按量表给回答打分，成本只算输入。第三方论文指出按评分细则判断质量是它的弱项，上线前先抽样对比。

    从文本里抽取判断条件：是否包含退款请求、是否提到竞品、是否需要回电，直接写进业务逻辑。

    对百万级记录逐条打标签再汇总，不限并发，输出免费，适合离线批量任务。

06 · LIMITATIONS

使用前先了解 Jev 的局限

以下来自 TypeSafe 官方说明。能用代码算的交给代码，一个问题只问一件事。

  • 按字面理解它回答你写下的问题，而不是你心里想问的问题，措辞要准确。
  • 不是计算器不适合数学和计数，这类逻辑用代码实现。
  • 日期与多跳推理偏弱日期先比、多步推理先拆，再交给 Jev 判断。
  • 无关内容会拖后腿state 里塞太多无关信息会降低准确率，只放需要判断的部分。
  • 提示注入风险state 里的不可信内容可能影响判断，关键场景要加防护。
  • 选项顺序偏差choice 问题对第一个选项略有偏好，可打乱顺序做校验。
  • 不生成文字没有对话、摘要、改写能力，需要文字请配合大模型使用。
  • 英文最好中文等其他语言可以用但效果较弱，建议问题优先用英文；jev-1.14.0 的多语言提升最明显。

08 · QUICKSTART

三步接入 jev-1.13.0 API

Jev 不兼容 OpenAI 接口，用普通 HTTP 请求调用 /v1/systemone。

  1. 注册并充值：在 anyaigc.ai 注册账号，余额对平台所有模型通用。
  2. 创建 API Key：在控制台创建令牌，复制以 sk- 开头的 Key，存到环境变量 ANYAIGC_API_KEY。
  3. 发起请求：向 https://anyaigc.ai/v1/systemone 发送 POST，model 填 jev-1.13.0，带上 state 和 questions。接口同步返回，不需要轮询。

单次请求控制在 32k tokens 以内。在 AnyAIGC 上，jev-1.13.0 上下文为 32k tokens。内容更长时，把内容拆成多次请求、删掉 state 里的无关文字，或换用 256k 上下文的 jev-1.14.0。

state 和问题建议用英文写。TypeSafe 称 Jev 的英文效果最好，中文也能用但准确率较低。中文业务可以把待判断内容原样放进 state、把 instructions 和 criteria 写成英文，上线前用自己的样本测一遍阈值。

返回示例的数值取自 AnyAIGC 接口文档。model 返回实际运行的版本；usage.output_tokens 不计费。请求体格式错误返回 400，Key 无效返回 401，错误体格式为 {"error": {"code", "message", "param", "type"}}。完整参数见 AnyAIGC System One 接口文档。

FAQ

jev-1.13.0 API 常见问题

jev-1.13.0 是什么？

jev-1.13.0 是 TypeSafe AI 的 System One 模型 Jev 的第一个公开版本，2026 年 9 月 15 日发布。System One 的名字来自卡尼曼提出的「系统 1」，也就是快速、直觉式的判断。你把要判断的内容（state）和若干个带类型的问题发给它，它返回带校准概率的类型化答案，而不是一段文字。在 AnyAIGC 上，jev-1.13.0 上下文 32k tokens，支持 noul、choice、score 三种问题类型。

jev-1.13.0 停用了吗？

没有停用。新版 jev-1.14.0 已于 2026 年 10 月 14 日发布，但 TypeSafe 没有公布 jev-1.13.0 的下线日期，目前在 AnyAIGC 上仍可正常调用。TypeSafe 表示下线 jev-1.13.0 前会提前 60 天通知。已经在 1.13 上调好阈值的业务可以继续使用，新项目建议用 jev-1.14.0。

jev-1.13.0 和 jev-1.14.0 有什么区别？

jev-1.13.0 是第一个公开版本（2026 年 9 月 15 日），上下文 32k tokens，文本输入，支持 noul、choice、score 三种问题类型。jev-1.14.0（2026 年 10 月 14 日）据 TypeSafe 介绍各方面都有小幅提升，多语言提升最明显；在 AnyAIGC 上上下文 256k tokens，并新增实验性的图片输入和 Box 问题类型。两个版本价格相同。

jev-1.13.0 API 兼容 OpenAI 接口吗？

不兼容。Jev 使用 TypeSafe 自己的 System One 接口：POST https://anyaigc.ai/v1/systemone，请求体是 model、state、questions，返回 answers 和 usage，没有 messages 和 choices。OpenAI SDK 不能直接调用，请用 requests、fetch 或 cURL 发普通 HTTP 请求，鉴权同样是 Authorization: Bearer <API Key>。接口是同步的，没有流式输出，也不需要轮询任务。

jev-1.13.0 有哪些局限？支持中文吗？

按 TypeSafe 官方说明：Jev 按字面理解问题；不擅长数学和计数（「Jev 不是计算器」），也不擅长日期比较和多跳推理；state 里无关内容太多会降低准确率；有提示注入风险；choice 问题对第一个选项略有偏好；不能生成文字。中文可以用，但英文效果最好，中文等其他语言准确率较低。第三方 arXiv 论文也指出它在低资源语言、带噪声的标签和按评分细则判断质量上偏弱。对准确率要求高的中文业务，建议把问题写成英文，或先用自己的样本测试。
