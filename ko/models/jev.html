01 · JEV란

Jev란: 문단이 아닌 결정

채팅 LLM은 직접 파싱해야 하는 텍스트를 돌려줍니다. Jev는 코드가 바로 쓸 수 있는 값, 즉 확률, 선택지, 점수를 돌려줍니다.

Jev는 TypeSafe AI의 첫 번째 공개 System One 모델입니다. 이름은 대니얼 카너먼의 "시스템 1", 즉 두뇌가 깊이 따져 보지 않고 내리는 빠르고 직관적인 판단에서 따왔습니다. TypeSafe에 따르면 Jev는 RLCD(Reinforcement Learning for Calibrated Decisions)와 병렬 샘플러로 학습했으며, 자유 텍스트 대신 보정된 확률이 담긴 타입 지정 답변을 반환합니다.

똑똑한 if 문이라고 생각하세요. 판단할 내용은 state에 넣고, 이름과 타입이 있는 질문을 questions에 정의하면, 모든 질문이 요청 한 번에 병렬로 답변되며 질문 수에 제한이 없습니다. TypeSafe는 요청한 타입과 스키마에 맞는 답변을 보장하므로 파싱이나 재시도 로직을 작성할 필요가 없습니다.

02 · 질문 유형

질문 유형 네 가지: noul, choice, score, box

questions에서 각 질문에 이름을 붙이면, 답변이 같은 이름으로 돌아옵니다.

  • type: noul

    noul참일 확률

    어떤 일이 참일 가능성은 얼마입니까? 0에서 1 사이의 확률을 반환합니다. instructions로 질문하거나, criteria에 true와 false를 설명하세요.

    요청 
    "is_urgent": {
  "type": "noul",
  "instructions": "Does this convey urgency?"
}
    답변 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice옵션 하나 선택

    criteria는 각 옵션 이름을 설명에 대응시키며, 옵션은 1개에서 255개까지입니다. 선택된 옵션, 신뢰도, 모든 옵션의 확률을 반환합니다.

    요청 
    "department": {
  "type": "choice",
  "criteria": {"billing": "…", "sales": "…", "technical": "…"}
}
    답변 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score척도로 평가

    criteria는 2개에서 10개 수준으로 이루어진 순서 있는 배열입니다. 확률 가중 점수(소수일 수 있음), 신뢰도, 범례, 수준별 확률을 반환합니다.

    요청 
    "frustration": {
  "type": "score",
  "criteria": ["Calm", "Frustrated", "Very angry"]
}
    답변 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · jev-1.14.0

    box이미지에서 객체 위치 찾기 실험적

    jev-1.14.0 전용입니다. assets에 이미지가 필요하며 헤더 TypeSafe-Danger-Zone-Images: true를 보내야 합니다. TypeSafe 문서에 따르면 답변은 객체의 위, 아래, 왼쪽, 오른쪽 가장자리를 0–1 비율로 알려 주며, null일 수 있는 신뢰도가 함께 옵니다.

    요청 
    "mug": {
  "type": "box",
  "instructions": "the coffee mug in `photo`"
}

05 · 활용 사례

Jev를 사용하는 팀의 활용 사례

코드가 분기하고, 정렬하고, 알림을 보낼 수 있는 결과가 필요한 곳이라면 어디든 쓸 수 있습니다.

  • 01 · choice

    분류와 의도 파악

    메시지, 상품, 문서를 고정된 카테고리로 분류하고 카테고리별 확률을 받으세요. 신뢰도가 낮은 건은 사람이나 LLM에 넘길 수 있습니다.

  • 02 · choice + noul

    티켓 라우팅

    요청 한 번으로 담당 팀, 긴급도, 고객의 불만 수준을 판단하므로 티켓을 누가 받고 대기열의 어디에 놓일지 알 수 있습니다.

  • 03 · score

    위험 점수화

    거래, 문서, 계정을 직접 정한 기준에 따라 점수화하세요. 점수는 확률 가중 소수이므로 임계값을 정하기 쉽습니다.

  • 04 · noul

    콘텐츠 검수

    댓글과 사용자 생성 콘텐츠의 위반 여부를 점검합니다. 정책 규칙마다 별도의 질문으로 두고 병렬로 답변합니다.

  • 05 · noul

    LLM 가드레일

    LLM 앞뒤에 점검 단계를 추가하세요. 탈옥과 프롬프트 인젝션을 탐지하고, 출력이 제공된 출처를 벗어나지 않았는지 검증합니다.

  • 06 · score

    채점과 평가

    응답을 척도로 채점해 LLM-as-judge 작업의 일부를 맡기고, 입력에만 비용을 내세요. 제3자 논문에 따르면 루브릭 방식의 품질 판단은 약점이므로, 의존하기 전에 표본을 직접 확인하세요.

  • 07 · if

    스마트 if 문

    텍스트에서 조건을 뽑아냅니다. 환불 요청인지, 경쟁사를 언급했는지, 고객이 콜백을 원하는지 등입니다. 그 답을 업무 로직에 바로 연결하세요.

  • 08 · map-reduce

    대규모 데이터셋 배치 처리

    수백만 건의 레코드에 하나씩 라벨을 달고 결과를 집계하세요. 동시 실행 제한 없음과 출력 무료는 오프라인 배치 작업에 알맞습니다.

  • 09 · realtime

    실시간 앱

    TypeSafe에 따르면 일반적인 응답은 약 100 ms로, 사용자 요청 경로 안에 넣을 수 있을 만큼 빠릅니다.

07 · 제한 사항

출시 전에 Jev의 한계를 알아 두세요

TypeSafe 공식 가이드 기준입니다. 코드로 계산할 수 있는 것은 코드에 맡기고, 질문 하나에는 하나만 물으세요.

  • 문자 그대로 해석의도한 질문이 아니라 쓴 질문에 답합니다. 정확하게 표현하세요.
  • 계산기가 아닙니다수학과 개수 세기는 맡기지 마세요. 그 로직은 코드로 처리하세요.
  • 날짜와 다단계 추론날짜는 직접 비교하고, 여러 단계의 추론은 나눈 뒤에 Jev에게 물으세요.
  • 관련 없는 state는 성능을 떨어뜨립니다무관한 내용이 많으면 정확도가 낮아집니다. 판단이 필요한 내용만 보내세요.
  • 프롬프트 인젝션state에 신뢰할 수 없는 콘텐츠가 있으면 답변이 흔들릴 수 있습니다. 중요한 곳에는 보호 장치를 추가하세요.
  • 첫 번째 옵션 편향choice 질문은 첫 번째 옵션 쪽으로 약간 치우칩니다. 순서를 섞어서 확인하세요.
  • 텍스트 생성 불가채팅, 요약, 재작성은 지원하지 않습니다. 문장이 필요하면 LLM과 함께 사용하세요.
  • 영어 우선영어에서 가장 잘 동작합니다. 다른 언어도 동작하지만 정확도가 낮습니다.

  2. API 키 만들기: 콘솔에서 토큰을 만들고 sk-로 시작하는 키를 복사해 ANYAIGC_API_KEY 환경 변수에 저장하세요.
  3. 요청 보내기: https://anyaigc.ai/v1/systemone에 POST하고, model은 jev-1.14.0으로, 그리고 state와 questions를 설정합니다. 응답은 동기식이므로 폴링할 필요가 없습니다. 모든 필드는 API 문서를 참고하세요.

영어에서 가장 잘 동작합니다. TypeSafe에 따르면 Jev는 영어에서 가장 강합니다. 다른 언어도 동작하지만 정확도가 낮습니다. 콘텐츠가 다른 언어라면 instructions와 criteria는 영어로 쓰고, 실서비스에 올리기 전에 직접 준비한 샘플로 임계값을 테스트하세요.

응답 값은 AnyAIGC API 문서에서 가져왔습니다. model은 실제로 실행된 버전을 알려 주며, usage.output_tokens는 과금되지 않습니다. 잘못된 본문은 400, 잘못된 키는 401을 반환하고, 오류 본문은 {"error": {"code", "message", "param", "type"}} 형태입니다. 전체 파라미터는 AnyAIGC System One API 문서에 있습니다.

10 · 이미지 & BOX

jev-1.14.0의 이미지 입력과 box 위치 지정

이미지를 base64로 인코딩해 assets에 넣고, state에서 그 플레이스홀더를 참조한 뒤 헤더 하나를 추가하세요.

실험적 기능입니다. TypeSafe 문서에 따르면 이미지는 PNG 또는 JPEG, 최대 16 MiB, 한 변 280–1568 px이며 일반 입력 토큰으로 과금됩니다. 요청에는 TypeSafe-Danger-Zone-Images: true를 포함해야 합니다. TypeSafe는 이미지와 box를 아직 프로덕션에 권장하지 않는다고 밝힙니다. 256k 긴 컨텍스트에도 헤더 TypeSafe-Danger-Zone-Long-Context: true가 필요합니다. AnyAIGC는 이 헤더와 assets를 그대로 전달합니다.

Box는 위치만 찾습니다. 예제는 box를 신뢰하기 전에 객체가 이미지에 있는지 확인하는 noul 질문을 추가합니다. 플레이스홀더는 단순한 문자열이므로, 실제 텍스트와 겹치지 않도록 이미지마다 새 랜덤 ID를 쓰세요.

FAQ

Jev API 자주 묻는 질문

Jev란 무엇입니까?

Jev는 TypeSafe AI가 처음 공개한 System One 모델입니다. 이름은 대니얼 카너먼의 "시스템 1", 즉 빠르고 직관적인 판단에서 따왔습니다. 판단할 콘텐츠(state)와 타입이 지정된 질문 묶음(questions)을 Jev에 보내면, 보정된 확률이 담긴 타입 지정 답변을 돌려줍니다. 어떤 범주에 속하는지, 문장이 참일 확률이 얼마인지, 척도에서 어디에 놓이는지를 알려 줍니다. TypeSafe에 따르면 Jev는 RLCD(Reinforcement Learning for Calibrated Decisions)와 병렬 샘플러로 학습했습니다.

Jev는 텍스트를 생성합니까? 채팅 모델로 쓸 수 있습니까?

아니요. Jev는 텍스트를 생성하지 않으며 채팅, 완성, 요약 기능이 없습니다. 사용자가 정의한 질문에만 답하고, 모든 답변은 요청한 유형(확률, 선택지, 점수)에 맞춰 반환됩니다. 글쓰기에는 같은 플랫폼의 GPT, Claude 같은 LLM을 쓰고, 분류, 라우팅, 모더레이션, 점수 산정에는 Jev를 쓰세요.

Jev API는 OpenAI 호환입니까? OpenAI SDK를 쓸 수 있습니까?

아니요. Jev는 TypeSafe 고유의 System One 인터페이스를 사용합니다. POST https://anyaigc.ai/v1/systemone에 model, state, questions(이미지는 assets 추가)를 본문으로 보내고, 응답은 answers와 usage이며 messages나 choices는 없습니다. OpenAI SDK로는 호출할 수 없으므로 requests, fetch, cURL로 일반 HTTP 요청을 보내세요. 인증은 그대로 Authorization: Bearer <API Key>입니다. 이 엔드포인트는 동기식이며 스트리밍과 작업 폴링이 없습니다.

Jev API 가격은 얼마입니까? 출력은 정말 무료입니까?

AnyAIGC에서 jev-1.14.0과 jev-1.13.0은 가격이 같습니다. 입력 100만 토큰당 $0.0227이고 출력은 무료입니다. 토큰 단위로 과금하며 입력 토큰에만 요금이 부과됩니다. 이미지도 일반 입력 토큰으로 계산합니다. 예를 들어 요청 1,000,000건에 건당 입력 300 토큰이면 총 300M 토큰이고 비용은 $6.81입니다. 모든 사용자에게 동시 실행 제한이 없습니다. 실시간 가격은 AnyAIGC 모델 카탈로그에서 확인하세요.

jev-1.14.0과 jev-1.13.0은 무엇이 다릅니까?

jev-1.13.0은 2026년 9월 15일에 출시된 첫 공개 버전이며 컨텍스트는 32k 토큰입니다. jev-1.14.0은 2026년 10월 14일에 출시되었습니다. TypeSafe는 전반적으로 소폭 개선되었고 특히 다국어 성능이 가장 크게 좋아졌다고 설명합니다. AnyAIGC에서는 256k 컨텍스트를 지원하고 실험적인 이미지 입력과 box 질문 유형이 추가되었습니다. 두 버전의 가격은 같으며 새 프로젝트에는 jev-1.14.0을 권장합니다.

Jev의 컨텍스트 길이는 얼마입니까?

AnyAIGC 모델 카탈로그 기준으로 jev-1.13.0은 32k 토큰, jev-1.14.0은 256k 토큰 컨텍스트를 지원합니다. TypeSafe 문서는 긴 컨텍스트를 쓰려면 요청 헤더 TypeSafe-Danger-Zone-Long-Context: true가 필요하다고 하며, AnyAIGC는 이 헤더를 그대로 전달합니다. 또한 TypeSafe는 긴 컨텍스트가 기본 길이보다 느리고 정확도도 낮다고 안내하므로, 가능하면 콘텐츠를 나눠서 보내세요.

Jev는 이미지를 입력받을 수 있습니까? box 질문 유형은 무엇입니까?

jev-1.14.0은 실험적인 이미지 입력을 지원합니다. base64로 인코딩한 PNG 또는 JPEG(최대 16 MiB, 한 변 280-1568 px)를 요청 본문의 assets에 넣고, state에서 해당 플레이스홀더를 참조한 다음 헤더 TypeSafe-Danger-Zone-Images: true를 보내세요. box는 1.14에서 추가된 실험적 질문 유형으로 이미지 속 물체의 위치를 찾으며, 같은 헤더와 이미지가 필요합니다. 이미지는 일반 입력 토큰으로 과금됩니다. TypeSafe는 이미지 기능을 아직 프로덕션에 권장하지 않는다고 밝혔습니다.

Jev는 어떤 언어를 지원합니까?

영어에서 가장 잘 동작합니다. TypeSafe에 따르면 다른 언어도 동작하지만 정확도가 낮고, jev-1.14.0은 1.13보다 다국어 성능이 향상되었습니다. 제3자 논문에서는 jev-1.13.0이 122개 언어의 Belebele에서 86.7% 정확도를 기록했고, 저자원 언어에서는 결과가 더 낮았습니다. 정확도가 중요하다면 질문을 영어로 작성하고, 서비스에 적용하기 전에 직접 가진 샘플로 테스트하세요.

Jev의 한계는 무엇입니까?

TypeSafe에 따르면 Jev는 표현을 문자 그대로 읽습니다. 수학이나 개수 세기에는 맞지 않으며("Jev is not a calculator"), 날짜 비교와 다단계 추론 질문에 약합니다. 관련 없는 state가 많으면 정확도가 떨어지고, 프롬프트 인젝션 위험이 있으며, 선택형 질문은 첫 번째 선택지로 약간 치우치는 경향이 있습니다. 또한 텍스트를 생성할 수 없습니다. 코드로 계산할 수 있는 것은 코드로 계산하고, 질문 하나에는 한 가지만 물어보세요.

Jev를 상업적으로 사용할 수 있습니까?

제품과 업무 워크플로에서 Jev를 호출할 수 있습니다. 상업적 이용은 TypeSafe 공식 약관을 따릅니다. TypeSafe는 고객 데이터로 학습하지 않는다고 밝혔습니다.

anyaigc.ai에서 가입하고 충전한 뒤, 콘솔에서 토큰을 만들고 sk-로 시작하는 키를 복사해 환경 변수 ANYAIGC_API_KEY에 저장하세요. 같은 키로 jev-1.14.0, jev-1.13.0과 플랫폼의 다른 300개 이상의 모델을 모두 호출할 수 있습니다.

WeChat Pay, Alipay, USDT, 신용카드로 충전할 수 있습니다. 잔액은 USD 기준이며 플랫폼의 모든 모델에서 사용할 수 있습니다. 인보이스는 콘솔에서 충전한 금액 기준으로 발급할 수 있습니다.

신규 사용자에게 무료 체험 크레딧이 있습니까?

네. 신규 계정에는 토큰 200만 개 분량의 체험 크레딧이 제공되므로 충전 여부를 결정하기 전에 먼저 테스트할 수 있습니다. 충전은 $1부터 가능합니다.

잔액을 환불받을 수 있습니까?

네. 사용하지 않은 잔액은 수수료 없이 환불받을 수 있습니다. 환불은 고객 지원에 문의해 진행하세요.

실제 모델이 맞습니까? 데이터는 안전합니까?

요청은 공식 모델 채널로 전달되며, 저가 모델이나 리버스 엔지니어링 방식의 대체 모델은 사용하지 않습니다. 법령에서 요구하는 경우를 제외하고 프롬프트와 출력을 영구 저장하거나 학습에 사용하지 않으며, 콘솔에서 모든 요청의 토큰 수와 비용을 확인할 수 있습니다.
