02 · 질문 유형

jev-1.14.0의 네 가지 질문 유형

questions에서 각 질문에 이름을 붙이세요. 답변은 같은 이름으로 돌아오며 모두 병렬로 계산되고, 질문 수에 제한이 없습니다.

  • type: noul

    noul참일 확률

    instructions로 질문하거나, criteria {"true": "…", "false": "…"}로 양쪽을 설명하세요. 0에서 1 사이의 확률을 반환합니다.

    answer 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choice옵션 하나 선택

    criteria는 옵션 이름을 설명에 매핑하며, 옵션은 1개에서 255개까지 지정할 수 있습니다. 선택한 항목, 신뢰도, 모든 옵션의 확률을 반환합니다.

    answer 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    score척도로 평가

    criteria는 2개에서 10개 수준으로 이루어진 순서 있는 배열입니다. 확률 가중 점수(소수), 신뢰도, 범례, 수준별 확률을 반환합니다.

    answer 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · 1.14에서 추가

    box객체 위치 찾기 실험적

    assets에 이미지가 필요하며 TypeSafe-Danger-Zone-Images: true 헤더를 보내야 합니다. TypeSafe 문서에 따르면 답변에는 객체의 위, 아래, 왼쪽, 오른쪽 가장자리가 0–1 비율로 담기고, null일 수 있는 신뢰도가 함께 제공됩니다.

    요청 
    "mug": {"type": "box", "instructions": "the coffee mug in `photo`"}

05 · 활용 사례

팀이 jev-1.14.0으로 만드는 것

코드가 분기하거나 순위를 매기거나 알림을 보낼 때 기준으로 삼을 값이 필요한 모든 곳에 사용할 수 있습니다.

  • 01 · choice

    분류와 의도 파악

    메시지, 상품, 문서를 정해진 클래스로 분류하고 각각의 확률을 받습니다. 신뢰도가 낮은 건은 사람이나 LLM에 넘기세요.

  • 02 · choice + noul

    티켓 라우팅

    담당 팀, 긴급도, 고객의 불만 정도를 한 번의 요청으로 판단하고, 그 답변을 바탕으로 바로 라우팅하고 우선순위를 정합니다.

  • 03 · score

    위험 점수화

    거래, 문서, 계정을 직접 정한 기준에 따라 점수화합니다. 가중치가 붙은 소수 값이라 임계값을 조정하기 쉽습니다.

  • 04 · noul

    콘텐츠 검수

    정책 규칙을 각각 하나의 질문으로 작성하면 모든 판정을 병렬로 받을 수 있습니다. 1.14의 다국어 향상은 여러 언어가 섞인 피드에 도움이 됩니다.

  • 05 · noul

    LLM 가드레일

    프롬프트가 LLM에 도달하기 전에 탈옥 시도를 확인하고, 출력은 사후에 출처와 대조해 확인합니다.

  • 06 · score

    LLM-as-judge 채점

    입력에만 비용을 내고 루브릭에 따라 응답을 채점합니다. 제3자 논문에서는 루브릭 방식의 품질 판단이 약점으로 나타났으니 먼저 표본으로 점검하세요.

  • 07 · if

    스마트 if 문

    텍스트에서 조건을 뽑아냅니다. 환불 요청인지, 경쟁사를 언급하는지, 고객이 콜백을 원하는지 등입니다.

    대규모 데이터셋 처리

    수백만 건의 레코드에 레이블을 붙이고 결과를 집계합니다. 동시 실행 제한 없음과 무료 출력은 오프라인 배치 작업에 적합합니다.

  • 09 · realtime

    실시간 앱

07 · 제한 사항

배포 전에 한계를 확인하세요

TypeSafe 자체 가이드 기준입니다. 코드로 할 수 있는 일은 코드에 맡기고, 질문 하나에는 한 가지만 물으세요.

  • 문자 그대로 해석의도한 질문이 아니라 작성한 질문에 답합니다. 표현을 신중하게 쓰세요.
  • 계산기가 아닙니다수학과 개수 세기는 피하고 코드에서 처리하세요.
  • 날짜와 멀티 홉날짜는 직접 비교하고, 여러 단계의 추론은 나눈 뒤에 Jev에 질문하세요.
  • 관련 없는 state는 해롭습니다256k의 여유가 있어도 질문에 필요한 내용만 보내세요.
  • 프롬프트 인젝션state에 신뢰할 수 없는 콘텐츠가 있으면 답변이 흔들릴 수 있습니다. 중요한 곳에는 보호 장치를 추가하세요.
  • 첫 번째 선택지 편향choice 질문은 첫 번째 선택지를 약간 선호합니다. 순서를 섞어 확인하세요.
  • 텍스트 생성 불가채팅, 요약, 재작성은 지원하지 않습니다. 문장 생성은 LLM과 함께 사용하세요.
  • 이미지는 실험 단계TypeSafe는 아직 이미지 입력이나 box를 프로덕션에 권장하지 않습니다.

09 · 빠른 시작

jev-1.14.0 API 시작하기

Jev는 OpenAI 호환이 아닙니다. 일반 HTTP로 /v1/systemone을 호출하세요.

  1. 가입 후 충전: anyaigc.ai에서 계정을 만드세요. 잔액은 모든 모델에서 공통으로 사용할 수 있습니다.
  2. API 키 생성: 콘솔에서 토큰을 만들고 sk-로 시작하는 키를 복사해 ANYAIGC_API_KEY에 저장하세요.
  3. 요청 보내기: https://anyaigc.ai/v1/systemone에 POST하고, model을 jev-1.14.0으로 설정한 뒤 state와 questions를 함께 보냅니다. 답변은 같은 응답으로 돌아옵니다.

응답 값은 AnyAIGC API 문서에서 가져왔습니다. model은 실행된 버전을 그대로 돌려주며, usage.output_tokens는 과금되지 않습니다. 잘못된 본문은 400, 잘못된 키는 401을 반환하며, 오류 본문은 {"error": {"code", "message", "param", "type"}} 형태입니다. 전체 파라미터는 AnyAIGC System One API 문서에서 확인하세요.

jev-1.14.0의 이미지, box, 긴 컨텍스트

이미지를 base64로 인코딩해 assets에 넣고, state에서 그 플레이스홀더를 참조한 뒤 헤더 하나를 추가하세요.

실험 기능입니다. TypeSafe 문서에 따르면 이미지는 PNG 또는 JPEG이어야 하고, 최대 16 MiB, 한 변 280–1568 px이며, 일반 입력 토큰으로 과금됩니다. 요청에는 TypeSafe-Danger-Zone-Images: true 헤더가 필요합니다. TypeSafe는 아직 이미지나 box를 프로덕션에 권장하지 않습니다. 256k 컨텍스트에도 옵트인 헤더 TypeSafe-Danger-Zone-Long-Context: true가 필요합니다. AnyAIGC는 이 헤더와 assets를 그대로 전달합니다.

Box는 위치만 찾습니다. 이 예제에서는 box를 사용하기 전에 대상이 실제로 있는지 확인하려고 noul 질문을 함께 넣었습니다. 플레이스홀더는 단순한 문자열이므로 state의 다른 텍스트와 겹치지 않도록 이미지마다 새로운 무작위 ID를 쓰세요. 긴 입력에는 같은 헤더에 TypeSafe-Danger-Zone-Long-Context: true를 추가하세요.

jev-1.14.0 API 자주 묻는 질문

jev-1.14.0이란 무엇입니까?

jev-1.14.0은 TypeSafe AI의 첫 공개 System One 모델인 Jev의 최신 버전으로, 2026년 10월 14일에 출시되었습니다. System One이라는 이름은 카너먼이 말한 빠르고 직관적인 판단에서 따왔습니다. 판단할 내용(state)과 타입이 지정된 질문 묶음을 보내면, Jev는 자유 형식 텍스트 대신 보정된 확률이 포함된 타입 지정 답변을 반환합니다. TypeSafe는 RLCD(Reinforcement Learning for Calibrated Decisions)와 병렬 샘플러로 학습했다고 밝힙니다.

jev-1.14.0은 jev-1.13.0과 무엇이 다릅니까?

TypeSafe에 따르면 jev-1.14.0은 전반적으로 소폭 향상되었고, 특히 다국어 입력에서 가장 크게 좋아졌습니다. 또한 이미지 속 객체의 위치를 찾는 실험적인 box 질문 유형이 추가되었습니다. AnyAIGC에서 jev-1.14.0의 컨텍스트 길이는 256k 토큰이며, jev-1.13.0은 32k입니다. 두 버전의 가격은 같습니다.

jev-1.14.0 API 요금은 얼마입니까?

AnyAIGC에서 jev-1.14.0은 입력 100만 토큰당 $0.0227이며 출력은 무료입니다. 입력 토큰만 과금되고, 이미지도 일반 입력 토큰으로 계산됩니다. 예를 들어 입력이 300 토큰인 요청 1,000,000건은 300M 토큰이며 비용은 $6.81입니다. 동시 실행은 모든 사용자에게 제한이 없습니다. 실시간 가격은 AnyAIGC 모델 카탈로그에서 확인하세요.

256k 컨텍스트는 어떻게 사용합니까?

AnyAIGC 카탈로그에는 jev-1.14.0이 256k 토큰 컨텍스트로 등록되어 있습니다. TypeSafe는 긴 컨텍스트를 사용하려면 옵트인 요청 헤더 TypeSafe-Danger-Zone-Long-Context: true를 요구합니다. AnyAIGC는 이 헤더를 그대로 전달합니다. 또한 TypeSafe는 관련 없는 state가 많으면 정확도가 떨어진다고 안내하므로, 가능하면 긴 입력을 나누어 보내세요.

jev-1.14.0에 이미지를 어떻게 보냅니까?

이미지를 base64로 assets 객체에 넣고({"type": "image", "format": "png", "data_base64": "..."}), state에서 그 플레이스홀더를 참조한 뒤 TypeSafe-Danger-Zone-Images: true 헤더를 추가하세요. TypeSafe에 따르면 이미지는 PNG 또는 JPEG이어야 하고, 최대 16 MiB, 한 변 280에서 1568 px이며, 일반 입력 토큰으로 과금됩니다. 이미지 입력은 실험 기능이며 TypeSafe는 아직 프로덕션 사용을 권장하지 않습니다.

box 질문 유형이란 무엇입니까?

Box는 jev-1.14.0만 지원하는 실험적인 질문 유형입니다. 이미지 asset에서 객체의 위치를 찾으며 TypeSafe-Danger-Zone-Images: true 헤더가 필요합니다. TypeSafe 문서에 따르면 답변에는 객체의 위, 아래, 왼쪽, 오른쪽 가장자리가 0에서 1 사이의 비율로 들어 있고, null일 수 있는 신뢰도도 함께 제공됩니다. 대상이 이미지에 있는지부터 확인하는 noul 질문과 함께 사용하세요.

jev-1.14.0 API는 OpenAI 호환입니까?

아니요. Jev는 TypeSafe의 System One 인터페이스를 사용합니다. POST https://anyaigc.ai/v1/systemone에 model, state, questions와 선택 항목인 assets를 보내면 answers와 usage가 반환됩니다. messages나 choices가 없으므로 OpenAI SDK로는 호출할 수 없습니다. requests, fetch, cURL 같은 일반 HTTP와 Authorization: Bearer <API Key> 헤더를 사용하세요. 호출은 동기 방식이며 스트리밍이나 작업 폴링은 없습니다.

jev-1.14.0은 얼마나 빠릅니까?

TypeSafe에 따르면 엔드투엔드 응답 시간은 70에서 500 ms입니다. TypeSafe는 자체 워크플로 평가에서 Jev가 LLM보다 193.6배 빠르고 444.6배 저렴하다고 보고하며, 이를 상한선에 해당하는 수치라고 설명합니다. 한 요청의 모든 질문은 병렬로 처리되며 AnyAIGC는 동시 실행을 제한하지 않습니다. 이 수치에 의존하기 전에 실제 워크로드에서 직접 측정하세요.

jev-1.14.0은 어떤 언어를 지원합니까?

영어가 가장 강합니다. 다른 언어도 동작하며, TypeSafe에 따르면 1.14의 주된 개선점이 다국어 품질입니다. 제3자 논문은 jev-1.13.0이 122개 언어 Belebele에서 86.7%를 기록했고 저자원 언어에서는 더 약하다고 측정했습니다. 서비스에 적용하기 전에 각 언어의 실제 샘플로 테스트하세요.

jev-1.14.0의 제한 사항은 무엇입니까?

TypeSafe에 따르면 Jev는 표현을 문자 그대로 해석하고, 수학이나 개수 세기에는 맞지 않으며("Jev is not a calculator"), 날짜 비교와 다단계 추론 질문에 약하고, 관련 없는 state가 많으면 정확도가 떨어지며, 프롬프트 인젝션 위험이 있고, choice 질문은 첫 번째 선택지를 약간 선호하며, 텍스트를 생성하지 않습니다. 코드로 계산할 수 있는 것은 코드로 계산하고, 질문 하나에는 한 가지만 물으세요.

jev-1.14.0을 상업적으로 사용할 수 있습니까?

TypeSafe의 공식 약관에 따라 자사 제품과 업무 워크플로에서 호출할 수 있습니다. TypeSafe는 고객 데이터로 학습하지 않는다고 밝힙니다.

jev-1.14.0 API 키는 어떻게 받습니까?

anyaigc.ai에서 가입하고 충전한 뒤 콘솔에서 토큰을 만들어 sk-로 시작하는 키를 복사하세요. 이 키는 ANYAIGC_API_KEY 환경 변수에 저장합니다. 같은 키로 jev-1.14.0, jev-1.13.0 및 플랫폼의 300개 이상의 다른 모델을 호출할 수 있습니다.
