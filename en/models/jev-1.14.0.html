02 · QUESTION TYPES

Four question types in jev-1.14.0

Name each question in questions. Answers come back under the same names, all computed in parallel, with no cap on how many you ask.

  • type: noul

    noulprobability it is true

    Ask with instructions, or describe both sides with criteria {"true": "…", "false": "…"}. Returns a probability from 0 to 1.

    answer 
    {"type": "noul", "noul": 0.95}
  • type: choice

    choicepick one option

    criteria maps option names to descriptions, 1 to 255 options. Returns the choice, a confidence and every option's probability.

    answer 
    {"choice": "billing", "confidence": 0.81,
 "probabilities": {"billing": 0.88, "sales": 0, "technical": 0.12}}
  • type: score

    scorerate on a scale

    criteria is an ordered array of 2 to 10 levels. Returns a probability-weighted score (a decimal), a confidence, a legend and per-level probabilities.

    answer 
    {"score": 1.05, "confidence": 0.92,
 "probabilities": {"0": 0, "1": 0.95, "2": 0.05}}
  • type: box · new in 1.14

    boxlocate an object Experimental

    Needs an image in assets and the header TypeSafe-Danger-Zone-Images: true. Per TypeSafe's docs, the answer gives the object's top, bottom, left and right edges as 0–1 fractions, plus a confidence that can be null.

    request 
    "mug": {"type": "box", "instructions": "the coffee mug in `photo`"}

07 · LIMITATIONS

Know the limits before you ship

From TypeSafe's own guidance. Let code do what code can do, and ask one thing per question.

  • Literal readingIt answers the question you wrote, not the one you meant. Word it carefully.
  • Not a calculatorAvoid math and counting. Do that in code.
  • Dates and multi-hopCompare dates and break down multi-step reasoning before asking Jev.
  • Irrelevant state hurtsEven with 256k of room, send only what the question needs.
  • Prompt injectionUntrusted content in state can sway answers. Add safeguards where it matters.
  • First-option biasChoice questions slightly favor the first option. Shuffle to check.
  • No text generationNo chat, summaries or rewrites. Pair it with an LLM for prose.
  • Images are experimentalTypeSafe does not yet recommend image input or box for production.

10 · IMAGES & BOX

Images, box and long context on jev-1.14.0

Base64-encode the image into assets, reference its placeholder from state, and add one header.

Experimental. Per TypeSafe's docs, images must be PNG or JPEG, up to 16 MiB, 280–1568 px per side, and are billed as normal input tokens. Requests need TypeSafe-Danger-Zone-Images: true. TypeSafe does not yet recommend images or box for production. The 256k context also needs an opt-in header, TypeSafe-Danger-Zone-Long-Context: true. AnyAIGC passes these headers and assets through.

Box only locates. The example adds a noul question to check that the object is there before you use the box. A placeholder is just a string, so use a fresh random ID per image to avoid clashing with other text in state. For long inputs, add TypeSafe-Danger-Zone-Long-Context: true to the same headers.

FAQ

jev-1.14.0 API FAQ

What is jev-1.14.0?

jev-1.14.0 is the latest version of Jev, TypeSafe AI's first public System One model, released on October 14, 2026. System One is named after Kahneman's fast, intuitive judgment. You send the content to judge (state) and a set of typed questions, and Jev returns typed answers with calibrated probabilities instead of free text. TypeSafe says it is trained with RLCD (Reinforcement Learning for Calibrated Decisions) and a parallel sampler.

What changed in jev-1.14.0 compared with jev-1.13.0?

According to TypeSafe, jev-1.14.0 brings small improvements across the board, with the biggest gain in multilingual inputs. It also adds the experimental box question type for locating objects in images. On AnyAIGC, jev-1.14.0 has a 256k-token context window versus 32k for jev-1.13.0. Both versions have the same price.

How much does the jev-1.14.0 API cost?

On AnyAIGC, jev-1.14.0 costs $0.0227 per 1M input tokens and output is free. Only input tokens are billed, and images count as normal input tokens. For example, 1,000,000 requests at 300 input tokens each is 300M tokens, which costs $6.81. Concurrency is unlimited for every user. Live prices are on the AnyAIGC model marketplace.

How do I use the 256k context window?

The AnyAIGC marketplace lists jev-1.14.0 with a 256k-token context. TypeSafe requires an opt-in request header for long context: TypeSafe-Danger-Zone-Long-Context: true. AnyAIGC passes this header through. TypeSafe also notes that large amounts of irrelevant state hurt accuracy, so split long inputs when you can.

How do I send images to jev-1.14.0?

Put the image in the assets object as base64 ({"type": "image", "format": "png", "data_base64": "..."}), reference its placeholder from state, and add the header TypeSafe-Danger-Zone-Images: true. Per TypeSafe, images must be PNG or JPEG, up to 16 MiB, 280 to 1568 px per side, and are billed as normal input tokens. Image input is experimental and TypeSafe does not yet recommend it for production.

What is the box question type?

Box is an experimental question type that only jev-1.14.0 supports. It locates an object in an image asset and needs the TypeSafe-Danger-Zone-Images: true header. Per TypeSafe's docs, the answer gives the object's top, bottom, left and right edges as 0 to 1 fractions plus a confidence that can be null. Pair it with a noul question that checks whether the object is there at all.

Is the jev-1.14.0 API OpenAI-compatible?

No. Jev uses TypeSafe's System One interface: POST https://anyaigc.ai/v1/systemone with model, state, questions and optional assets, and it returns answers and usage. There are no messages or choices, so OpenAI SDKs cannot call it. Use plain HTTP with requests, fetch or cURL and the header Authorization: Bearer <API Key>. Calls are synchronous, with no streaming and no task polling.

How fast is jev-1.14.0?

According to TypeSafe, end-to-end responses take 70 to 500 ms. On its own workflow evals TypeSafe reports Jev as 193.6x faster and 444.6x cheaper than LLMs, which it calls the high end. All questions in a request are answered in parallel, and AnyAIGC does not cap concurrency. Measure on your own workload before you rely on these numbers.

Which languages does jev-1.14.0 support?

English is strongest. Other languages work, and multilingual quality is the main improvement in 1.14 according to TypeSafe. A third-party paper measured jev-1.13.0 at 86.7% on Belebele across 122 languages and found it weaker on low-resource languages. Test with your own samples in each language before going live.

What are the limitations of jev-1.14.0?

Per TypeSafe: Jev reads your wording literally; it is not for math or counting ("Jev is not a calculator"); it is weak at date comparisons and multi-hop questions; large irrelevant state hurts accuracy; prompt injection is a risk; choice questions slightly favor the first option; and it does not generate text. Compute what code can compute, and ask one thing per question.
